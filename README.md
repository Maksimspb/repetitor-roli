# 🎭 Репетитор роли

Веб-тренажёр для заучивания текста роли в спектакле. Партнёр по сцене озвучивает
чужие реплики голосом, ты говоришь свои по памяти — учишь **связки** «реплика → ответ».
Приложение **слушает микрофон**, показывает вживую что расслышало и в конце сцены
выдаёт **сводку: где попал, где нет, процент точности**.

Пьеса по умолчанию: **«Волки и овцы»** А. Н. Островского (расширенная версия с народом и песней).

## 📱 Открыть на телефоне (в т.ч. в машине)

**Живая версия: https://maksimspb.github.io/repetitor-roli/**

Поставить на iPhone как приложение: открой ссылку в **Safari** → кнопка «Поделиться» →
**«На экран „Домой“»**. Появится иконка 🎭, запускается на весь экран.

- **Режим «🚗 Без рук (для машины)»** — включи в настройках перед стартом. Партнёр играет
  сцену сам, делает паузу под твою реплику. Телефон трогать не надо, **микрофон не нужен —
  работает офлайн** (после первого открытия). Идеально для машины.
- ⚠️ **На телефоне открывай только https-ссылку выше.** Если зайти с телефона на
  `http://<ip-компа>:8777`, браузер не выдаст микрофон вообще: соединение незащищённое.
  Это самая частая причина «микрофон не работает». Приложение теперь говорит об этом прямо.
- **Проверка микрофона** — в настройках, кнопка «🎙 Проверить микрофон»: 7 шагов, включая
  главный — «голос партнёра → микрофон». Именно на этом переходе Bluetooth-наушники
  переключают аудиомаршрут и рвут распознавание.
- **Точная проверка текста на телефоне.** Whisper прямо в браузере проверен и оказался
  непригоден (см. ниже), поэтому на телефоне работает браузерное распознавание. Если нужна
  точность Whisper — подними на Маке туннель и вставь его адрес в настройках:
  ```bash
  cloudflared tunnel --url http://localhost:8788     # выдаст https://…trycloudflare.com
  ```
  Настройки → «Сервер распознавания (Whisper)» → вставить адрес. Телефон начнёт слать
  реплики на Мак: та же скорость и точность, что за столом, ничего не качается на телефон.

> **Зачем это.** Существующие приложения для актёров (LineLearner, coldRead, ScenePartner…)
> — англоцентричны и заточены под короткие киносайды. **Пословной проверки текста
> на русском для театральной пьесы нет ни у кого** — это и есть ниша проекта.
> Подробнее — [`docs/MARKET-RESEARCH.md`](docs/MARKET-RESEARCH.md).

## Быстрый старт

```bash
git clone <repo-url> репетитор-роли
cd репетитор-роли
pip3 install python-docx        # только для пересборки пьесы из docx
./run.sh
```

Открой **http://localhost:8777** на Маке, или с телефона в той же Wi-Fi —
адрес `http://<ip-мака>:8777` скрипт покажет сам.

> Требуется Python 3. Ничего больше для запуска не нужно — TTS и распознавание
> речи работают в браузере (Web Speech API).

## Как пользоваться

1. Выбери **свою роль** — роль запоминается, в следующий раз выбирать не надо.
2. Появится список **только тех сцен, где роль есть** — с описанием (с кем сцена,
   сколько твоих реплик, первая строка). Выбери сцену или «▶ Все мои сцены подряд».
   На карточке видно, что со сценой уже было: `⏸ 5/14` — не закончена,
   `✓ рекорд 87%` — лучший результат за полный проход.
3. В «⚙ Показ реплик, голос, микрофон» — **режим показа**: скрыто / первые буквы
   (`Г···· С·····`) / целиком; голос, скорость, проверка микрофона.
4. **Начать репетицию** (кнопка всегда внизу экрана).
   - **Партнёр** (не твоя роль) — приложение показывает и **озвучивает** реплику, идёт дальше.
   - **Твоя реплика** — текст скрыт, в нижней панели горит 🔴 «слушаю», вживую печатается
     распознанное. Рядом — твой **рекорд по этой реплике**. Сказал — жмёшь **Дальше**
     (или `пробел`). Реплика раскрашивается: зелёное — попал, красное — пропустил.
     Кнопка 👁 — если забыл. **Aa** в шапке — размер текста.
5. **Выйти можно в любой момент** — стрелка «‹» в шапке (или `Esc`). Место сохраняется:
   сцена помечается как незаконченная, при возврате предлагается «Продолжить» или «Сначала».
   Продолжение показывает две последние реплики, чтобы поймать контекст.
6. В конце — **сводка**: точность, разбор ошибок (худшие сверху) и сравнение с рекордом.

## Точная проверка речи (Whisper)

Браузерное распознавание (Web Speech) **постоянно отваливается** — засыпает, перестаёт
слышать микрофон. Лечится локальным **Whisper**: реплика пишется через микрофон и
распознаётся на этом Маке. Точно, стабильно, приватно, офлайн.

**Установка (один раз):**
```bash
python3.11 -m venv .venv-asr          # нужен Python 3.11 (у 3.14 нет колёс ctranslate2)
.venv-asr/bin/pip install faster-whisper
```
Дальше `./run.sh` сам поднимет ASR-сервер на `:8788` (первый запуск скачает модель ~460 МБ).
Приложение на `http://localhost:8777` увидит бэкенд и переключится само — покажет тост
«Точное распознавание (Whisper) подключено». Микрофон разрешить в браузере.

- **Модель:** `small` (хороша для русского). Быстрее/легче — `ASR_MODEL=base ./run.sh`.
- **Где работает:** три движка распознавания, выбираются автоматически по доступности:
  1. **сервер faster-whisper** на Маке (быстрее и точнее всего);
  2. **Whisper прямо в браузере** (transformers.js / ONNX-WASM) — на телефоне и вообще без сервера,
     офлайн после первой загрузки; модель `Xenova/whisper-base` качается один раз (~базовая),
     на телефоне распознавание ~2–3 с на реплику. Первую загрузку делай по Wi-Fi;
  3. браузерный Web Speech — крайний случай.
- Как устроено — [`docs/VOICE.md`](docs/VOICE.md) и `asr_server.py`.

Сначала прочитай [`docs/DEVLOG.md`](docs/DEVLOG.md) — там текущее состояние, принятые

## Известные ограничения

- **Голос партнёра — живой** (Microsoft Neural через `edge-tts`, свой тембр на персонажа),
  пред-рендерен в `audio/` и работает офлайн из кеша. Как устроено и как перегенерировать —
  [`docs/VOICE.md`](docs/VOICE.md). Системный голос остаётся аварийным фолбэком.
- **Распознавание речи:** на Маке с запущенным Whisper (`./run.sh`) — точно и стабильно
  (см. «Точная проверка речи» выше). Без бэкенда (телефон, GitHub Pages) откат на
  браузерный Web Speech, который капризничает — но на телефоне проверка и не нужна.
- **Микрофон и звук не могут работать одновременно.** Приложение отпускает микрофон на время
  реплики партнёра и поднимает его обратно с паузой (по умолчанию 320 мс). На Bluetooth-гарнитуре
  переключение маршрута A2DP↔HFP занимает больше — если срывы повторяются, приложение само
  увеличивает паузу, а чистая диагностика возвращает её обратно. Проводные наушники или
  встроенный микрофон надёжнее беспроводных.
- Прогресс, рекорды и настройки лежат в `localStorage` **этого браузера**. Другой браузер или
  режим инкогнито — чистый лист; синхронизации между устройствами нет.
