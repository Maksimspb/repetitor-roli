# Архитектура

Три слоя, каждый — отдельная фаза разработки.

```
┌─ ПАРСЕР (parse.py) ───────────────────────────────────┐
│ docx → data/play.json                                  │
│ структура: акт → явление → реплика                     │
│ {speaker, canon.имя, action, inline_actions, text}     │
└────────────────────────────────────────────────────────┘
        ↓  data/play.json
┌─ ПРИЛОЖЕНИЕ (index.html) ─────────────────────────────┐
│ Партнёр:  выбрал роль → TTS озвучивает чужие реплики   │
│ Проверка: Web Speech ASR слушает → пословный дифф →    │
│           подсветка ошибок → сводка в конце сцены      │
└────────────────────────────────────────────────────────┘
        ↑  раздаёт
┌─ СЕРВЕР (server.py) ──────────────────────────────────┐
│ http на :8777, Cache-Control: no-store (правки сразу)  │
└────────────────────────────────────────────────────────┘
```

Сознательно **без сборки и фреймворков**: один HTML-файл + один Python-парсер + статик-сервер.
Клонировал → `./run.sh` → работает. TTS и распознавание — браузерные (Web Speech API),
поэтому бэкенд не нужен.

## Фаза 0 — Парсер (`parse.py`)

Вход: `data/play.docx` (python-docx). Выход: `data/play.json`.

### Формат `play.json`
```jsonc
{
  "meta": {
    "title": "...", "author": "...",
    "roles": [{"name": "Лыняев", "lines": 121}, ...],   // отсортировано по числу реплик
    "total_units": 1197, "total_lines": 955
  },
  "units": [                       // плоский список в порядке чтения
    {"type": "act",   "title": "Действие первое"},
    {"type": "scene", "title": "Явление первое", "act": "...",
     "participants": ["Павлин","Столяр",...],   // кто говорит в явлении (для фильтра по роли)
     "per_role": {"Павлин": 5, ...},            // сколько реплик у каждого
     "n_lines": 12, "preview": "Павлин: ..."},  // для короткого описания сцены
    {"type": "line",  "speaker": "Павлин", "speaker_raw": "Павлин",
     "chorus": false, "action": "подавая руку", "inline_actions": ["Прочим."],
     "text": "...", "act": "...", "scene": "..."},
    {"type": "stage", "text": "Крестьяне уходят."},   // ремарки/народные сцены
    {"type": "song",  "lines": [...]}                  // куплеты
  ]
}
```

### Засады формата и как решены
Разбирался драматургический текст «Волки и овцы» (расширенная версия). Реальные проблемы:

1. **Разнобой в написании имён** — `Анфуса/Анфиса`, `Мурзавецкий/Мурзовецкий`,
   `Аполон/Апполон`, `Подрядчик/Подрячик`. → Канонический словарь `CANON` (имя → варианты),
   обратный индекс `VAR2CANON`. Иначе одна роль раскалывается на несколько.
2. **Ремарки под видом реплик** — `Входит Купавина`, `Уходят`. → Список `STAGE_STARTS`;
   если «имя» начинается с этих слов — это `stage`, не реплика.
3. **Два разделителя реплики** — точка (887×) и двоеточие (69×). → Регэксп ловит оба.
4. **Хоровые реплики** — `Павлин и Влас хором:`, `Все:`, `Голоса:`. → `resolve_speaker`
   разбивает по «и»/запятой, если все части — известные роли, помечает `chorus:true`.
   (Курьёз пьесы: народный куплет подписан `Анфиса и Анфуса` — обе орфографии как «соавторы»;
   канон корректно сливает их в одну роль Анфуса.)
5. **Ремарки внутри реплики** — `(подавая руку)`, `(Прочим.)`. → `action` (перед репликой)
   и `inline_actions` (внутри) выносятся отдельно; при озвучке партнёром вырезаются
   (`speak()` чистит скобки), чтобы не читались вслух.

### Проверка разбора
`parse.py` печатает отчёт: число реплик по ролям, список «неизвестных» говорящих
(не из канона — глазами проверить, не опечатка ли), число ремарок.
На эталонной пьесе: **955 реплик, 20 ролей, 5 действий, 50 явлений, 183 ремарки**, неизвестных — нет.

## Фаза 1 — Партнёр (`index.html`)

- **Выбор роли** → `renderScenes()` фильтрует `SCENES` по `participants.includes(ROLE)`,
  показывает только сцены роли с описанием (участники, `per_role`, `preview`).
- **Выбор сцены** → `SELECTION` = массив диапазонов `[startI, endI]` в `units`
  (одна сцена или все сцены роли подряд).
- **Ход сцены** (`step()`): идёт по `sceneUnits`.
  - `act`/`scene` → разделитель, авто-дальше.
  - `stage`/`song` → тусклая подсказка, показать ~0.5с, авто-дальше.
  - `line`, чужая → **партнёр**: показать + `speak()` (Web Speech TTS, ru), по `onend` авто-дальше.
  - `line`, твоя → скрыть по `REVEAL` (`hidden`/`firstletters`/`full`), ждать кнопку.
- **TTS-голос**: `pickVoice()` ранжирует русские голоса (`voiceRank`): Siri > Premium >
  Enhanced > базовый; авто-выбор лучшего. Базовая Milena звучит «металлически» — нужен Enhanced.

## Фаза 2 — Проверка (браузерная, `index.html`)

- **Распознавание**: `webkitSpeechRecognition`, `lang='ru-RU'`, `interimResults`,
  `continuous`. На твоей реплике `listenStart()` — живой транскрипт в `.heard`
  («слышу: …») = обратная связь, что комп слышит.
- **Пословный дифф** (`wordDiff`): нормализация (`normWords`: lower, ё→е, снять пунктуацию/скобки),
  выравнивание **LCS** между оригиналом и распознанным. Каждое слово оригинала → `ok`/miss.
  `score = попаданий / всего слов оригинала * 100`. Даёт честный «что сказал / что в тексте».
- **Раскраска** реплики: зелёное (`.ok`) / красный пунктир (`.miss`), тег `%`.
- **Сводка** (`finish()`): общий средний %, счётчики «уверенно/провалено»,
  разбор каждой реплики (худшие сверху) с раскраской и «услышано: …».

### Ограничения браузерного ASR
Web Speech API облачный (Safari → Apple, Chrome → Google), нужен интернет; на русском
качество среднее. **Фаза 2+**: заменить на локальный Whisper (faster-whisper) + forced
alignment — точнее, офлайн, приватно. Тогда появляется маленький Python-бэкенд:
`браузер (MediaRecorder) → POST /asr → Whisper → JSON с таймингами → тот же wordDiff`.

## Фаза 2.1 — Навигация, прогресс, устойчивый микрофон (`index.html`)

### Экраны
`screen(name)` переключает три секции: `#setup` (роль → сцена → настройки),
`#stage` (репетиция), `#miccheck` (диагностика). Нижняя панель `#bar` и подсказка `#hint`
живут на всех экранах и наполняются тем, кто экран рисует. Все основные действия —
в панели внизу: список сцен длинный, кнопка в конце страницы требовала бы прокрутки назад.

### Хранилище (`localStorage`)
| Ключ | Что | Зачем |
|---|---|---|
| `rr.prefs.v1` | роль, режим показа, голос, скорость, размер текста, последняя сцена, `settle` | не переспрашивать одно и то же каждый запуск |
| `rr.progress.v1` | по ключу `роль::сцена`: `pos`, `doneLines/myLines`, `done`, `best`, `last`, `runs`, `results` | выход и возврат, метки в списке, рекорд по сцене |
| `rr.linebest.v1` | `id реплики → лучший %` | рекорд по каждой реплике |

`pos` — индекс в плоском массиве `units` прогона; `len` рядом с ним страхует от смены пьесы.
`best` пишется **только за полный проход**, иначе брошенный после двух лёгких реплик прогон
дал бы фальшивые 100%. `results` хранится без токенов раскраски — они пересчитываются
`wordDiff(orig, said)` при отрисовке разбора.

### Менеджер микрофона (`Mic`)
Одна точка владения `SpeechRecognition` на всё приложение. Ключевое:

- `engage(bubble)` — отпустить прошлую сессию, **дождаться** её реального конца,
  выждать `PREFS.settle` (пауза на переключение аудиомаршрута) и поднять новую.
- `release()` — промис, который резолвится по фактическому `onend`, а не сразу.
  Вызывается перед каждой репликой партнёра: звук и микрофон одновременно не живут.
- `finish()` — мягкий `stop()` с ожиданием финального результата (до 700 мс), чтобы
  последние слова попали в оценку.
- `gen` — счётчик поколений: колбэки мёртвых сессий отбрасываются, иначе поздний `onend`
  от abort-нутого движка перезапускал бы уже неактуальную сессию.
- Сторожевые таймеры: `T_START` (1.8 с без `onstart` → перезапуск) и `T_IDLE`
  (20 с без единого события у «живой» сессии → перезапуск).
- Коды ошибок разведены: `no-speech`/`aborted` — штатный конец, поднять молча;
  `network`/`audio-capture` — перезапуск с сообщением; `not-allowed`/`service-not-allowed` —
  терминально, повторять бессмысленно. Терминальные состояния (`TERMINAL`) защищены от
  затирания приходящим следом `onend`.
- `PREFS.settle` растёт сам (320 → 500 → 900 → 1400 мс), если сессия не поднимается
  восемь раз подряд: почти всегда это медленный Bluetooth-маршрут. Чистая диагностика
  возвращает 320.

Состояние всегда отражено чипом в нижней панели (`paintMic`), тап по нему — ручной подъём.

### Озвучка партнёра
`voicePartner` обязан завершиться: и `ended` у mp3, и `onend` у синтеза умеют не прийти
(Safari). Сторожевой таймер стартует с 9 с и подтягивается к реальной длительности файла
по `loadedmetadata` (`duration/rate + 3 с`); для синтеза считается по числу слов.

### Диагностика (`#miccheck`)
Семь шагов: защищённый контекст (`isSecureContext` — по `http://<ip>` микрофона не будет
никогда), движок, разрешение, устройство записи (`track.label` показывает, гарнитура или
встроенный), уровень сигнала через `AnalyserNode`, распознавание, и переход
«звук партнёра → микрофон». Поток `getUserMedia` закрывается **до** шагов с распознаванием:
открытый стрим конкурирует с `SpeechRecognition`.

## Фаза 3 — Умное (план)

- **LLM-судья перифраза**: отличать «своими словами, но верно» от реальной ошибки/пропуска.
- **Авто-передача хода**: не по кнопке, а по паузе/окончанию реплики (как coldRead).
- **Интервальные повторения (SRS)**: реплики с низким % возвращать чаще; кривая забывания.
- **Голос на персонажа**: разные TTS-голоса разным ролям.
